A. wait(), notify(), notifyAll()
=========================
1️⃣ What is the purpose of wait() in Java?

wait() releases the monitor lock and puts the current thread into the WAITING state until another thread calls notify() or notifyAll() on the same object.

2️⃣ Why must wait() and notify() be called inside a synchronized block?

Because both methods require that the calling thread owns the object's monitor.
Otherwise, Java throws IllegalMonitorStateException.

3️⃣ Difference between wait() and sleep()?
Feature	wait()	sleep()
Releases lock?	✔ Yes	❌ No
Inside synchronized?	✔ Required	❌ Not required
Wake-up triggered by?	notify()/notifyAll()	Time duration
Part of which class?	Object	Thread
4️⃣ What is a spurious wakeup, and how do you handle it?

A thread waiting using wait() may wake up without a notify() call.
Solution: Always use wait() inside a while loop, not an if.

while(conditionIsFalse) {
    lock.wait();
}

5️⃣ Difference between notify() and notifyAll()?

notify() wakes one waiting thread

notifyAll() wakes all waiting threads

Use notifyAll() for multi-producer/consumer to avoid missed notifications.

6️⃣ What happens after a thread is notified?

It becomes BLOCKED until it re-acquires the monitor lock again.

7️⃣ What is the lifecycle of a waiting thread?

WAITING → (notified) → BLOCKED → RUNNABLE → RUNNING

8️⃣ Can you call wait() on a Thread object?

Yes, because wait() belongs to Object, but you must synchronize on that thread instance.

9️⃣ What is the common mistake in wait/notify?

Calling wait() or notify() outside synchronized → runtime error.

B. Producer–Consumer (wait/notify)
=========================
10️⃣ Describe the Producer–Consumer problem.

It's a classic concurrency pattern where:

Producer generates data

Consumer processes data

Both coordinate using shared buffer

Producers wait when buffer is full

Consumers wait when buffer is empty

1️⃣1️⃣ Why do we use while inside producer/consumer?

Prevent:

Spurious wakeups

Incorrect wakeups when multiple threads compete

1️⃣2️⃣ Why is notifyAll() safer than notify() here?

If notify() wakes a thread that cannot proceed, the system may deadlock.
notifyAll() ensures all waiting threads get a chance.

1️⃣3️⃣ What if consumer starts before producer?

Consumer will call:

while(queue.isEmpty()) wait();


So it will wait safely.

1️⃣4️⃣ What happens if producer calls notify before consumer waits?

Consumer waits forever → MISSED NOTIFICATION
Fix: use BlockingQueue or start consumer first.

1️⃣5️⃣ Why BlockingQueue is preferred over wait/notify?

Because it handles:

Blocking

Signalling

Boundaries

Thread-safety

Automatically.

C. Deadlock
=========================
1️⃣6️⃣ What is a deadlock?

A situation where two or more threads wait forever because each holds a resource the other needs.

1️⃣7️⃣ What are the four conditions for deadlock?

Mutual exclusion

Hold and wait

No preemption

Circular wait

If all four occur → deadlock.

1️⃣8️⃣ Explain your deadlock example.

Thread-1 locks lock1 → waits for lock2

Thread-2 locks lock2 → waits for lock1
Both wait forever → circular dependency.

1️⃣9️⃣ How do you detect deadlock in Java?

Using:

jstack <pid>


Look for BLOCKED (on object monitor) with a cycle.

2️⃣0️⃣ How to prevent deadlock?

Acquire locks in fixed global order

Use tryLock() with timeout

Avoid nested locks

Use higher-level concurrent utilities (BlockingQueue, ExecutorService)

2️⃣1️⃣ How does tryLock() help avoid deadlock?

It lets a thread back off if the lock is unavailable:

if(lock.tryLock(1, TimeUnit.SECONDS)) { ... }
else { retry / exit }

=========================
2️⃣2️⃣ What is a race condition?

Two threads modify shared data without synchronization → unpredictable results.

2️⃣3️⃣ Why is count++ not thread-safe?

It involves 3 steps:

Read

Increment

Write

Threads can interleave between these steps.

2️⃣4️⃣ How to fix race conditions?

synchronized block

synchronized method

ReentrantLock

AtomicInteger

Thread confinement

Method	Block
Locks this	Can lock any object
Larger area locked	Smaller critical section
Less flexible	More flexible
2️⃣6️⃣ What happens if two threads call two different synchronized methods on same object?

Both are synchronized on this → only one thread executes at a time.

2️⃣7️⃣ What if synchronized static methods are used?

They lock Class object, not instance.

F. ReentrantLock
=========================
2️⃣8️⃣ What is ReentrantLock?

A lock with advanced capabilities compared to synchronized:

tryLock()

lockInterruptibly()

fair locking

multiple condition variables

2️⃣9️⃣ When do you prefer ReentrantLock over synchronized?

When you need:

Fairness

Timed lock attempts

Interruptible locks

Multiple conditions

More detailed lock control

3️⃣0️⃣ Difference between lock.lock() and tryLock()?

lock() → waits forever

tryLock() → returns immediately (or with timeout)

3️⃣1️⃣ Why must unlock() be inside finally block?

To prevent lock-forgetting on exceptions → deadlocks.

G. AtomicInteger
=========================
3️⃣2️⃣ What is AtomicInteger?

A lock-free thread-safe integer using CAS (compare-and-swap).

3️⃣3️⃣ Why is AtomicInteger faster than synchronized?

Because it avoids context switching & lock acquisitions.

3️⃣4️⃣ When should you NOT use AtomicInteger?

When operations involve multiple shared variables — CAS cannot guarantee grouping.

=========================
3️⃣5️⃣ What are the advantages of thread pools?

Reuse existing threads

Better performance

Graceful shutdown

3️⃣6️⃣ What is the difference between submit() and execute()?
execute()	submit()
No return	Returns Future
Cannot track failure	Exceptions captured in Future
3️⃣7️⃣ Why should you shutdown ExecutorService?

Because threads keep running even after main ends → memory leak.

3️⃣8️⃣ What is the difference between shutdown() and shutdownNow()?

shutdown() → finishes ongoing tasks

shutdownNow() → interrupts tasks, stops immediately

I. Advanced Concept Q’s
=========================
3️⃣9️⃣ Difference between Deadlock, Livelock, Starvation?
Term	Meaning
Deadlock	Threads wait forever holding locks
Livelock	Threads keep changing state but make no progress
Starvation	A thread never gets CPU/lock due to fairness issues
4️⃣0️⃣ What is monitor lock?

Every object in Java has an intrinsic lock (monitor lock) used by synchronized.

4️⃣1️⃣ What is re-entrant locking?

A thread holding a lock can re-acquire it multiple times → prevents self-deadlock.

4️⃣2️⃣ What causes “Missed signal” problem?

Calling notify() before the waiting thread calls wait().

4️⃣3️⃣ What are "Guarded Blocks"?

Wait conditions wrapped inside while loops — essential concurrency pattern.
